# V2 diagnostic measurement plan before choosing a repair

**Status:** Author-confirmed initial scope. The opt-in observer and pilot matrices are implemented and locally checked, but no author-run diagnostic has been dispatched and no V2 treatment is registered. [Design issue #119](https://github.com/FedMAQ/fedmaq-experiments/issues/119) owns the branch choice; [#120](https://github.com/FedMAQ/fedmaq-experiments/issues/120) owns the exact protocol after that choice.

## Why another measurement is needed

The [V1 round reread](2026-09-24-v1-round-telemetry-diagnostic-inventory.md) and [registered paired first-study readout](../../../fedmaq-analyses/reports/study1_replacement_2026_09_23/README.md) show three reasons to investigate. FedMAQ trails FedPAQ at the registered common bidirectional-byte budget in all five benchmark conditions. The pipeline-free no-KD ablation improves the terminal CIFAR-10 score in all six paired seeds, but its severe-skew common-budget signs are mixed. The benchmark and ablation use different `post_process` settings, so their effect sizes cannot be transferred. V1 also records frequent Tier-1 binding and a mismatch between snapped pre-cap and applied bit-width histograms. These observations identify questions; none identifies the weak component.

The archived round logs omit same-round performance before and after KD, ensemble performance, individual teacher quality, client-keyed bit assignments, and quantization distortion. They contain final post-round evaluation and aggregated planner/KD summaries. A fresh instrumented run is therefore needed to locate the failure before selecting a repair. V1 test trajectories were already reread to generate these hypotheses; any later reuse of the same test images is exploratory rather than an independent confirmation.

## Initial scope and invariants

- Keep the selected power-mean rule (`p=0.5`, `omega=0.5`), permissible bit-width set, Tier-1 memory ceiling, quantizer, client training, and proxy set fixed in the first diagnostic. Do not alter the frozen V1 configuration or evidence. Put instrumentation behind a new diagnostic configuration and output identity.
- Distinguish **model aggregation**, which produces the parameter-average student from reconstructed client updates, from **teacher pooling**, which combines participating teachers' predictions on each proxy image. Diagnose these and the student KD update separately.
- Use the same validation loader to evaluate the parameter-average student immediately before KD, the current teacher ensemble, and the resulting student immediately after KD within each observed round. This validation set has already supported V1 selection, so the diagnosis remains exploratory. Preserve model evaluation/training modes, random-number-generator state, and deterministic ordering. An observer evaluation must not update models, select teachers, alter the proxy pool, or feed validation labels into KD.
- Keep method communication accounting as cumulative bidirectional bytes. Record observer-only evaluation time separately from method server compute and wall time; any computation introduced by a later treatment must be charged under that treatment's protocol.
- Only the thesis author runs GPU/JupyterHub jobs. Local implementation checks and a small smoke may validate instrumentation, but no result from a smoke is a scientific verdict.

## Minimum instrumented record

| Question | Record per observed round | Existing seam |
|---|---|---|
| Does this round's KD update improve the student? | Same-validation-set accuracy, cross-entropy, and class-level counts for parameter-average and post-KD students; their paired difference. Retain existing KD loss, skipped-step, and dropped-teacher status. | `TelemetryFedAvg.aggregate_fit` calls FedAvg before the FedMAQ KD hook; `distill_ensemble_into_global` initializes the student from that average. The normal evaluation runs only after the hook ([`strategy.py`](../../src/fedmaq/core/strategy.py#L260), [`kd_utils.py`](../../src/fedmaq/core/kd_utils.py#L162)). |
| Is the teacher target useful and transferable? | On that same validation set, pooled-ensemble accuracy, loss, confidence/calibration summary, class-level counts, teacher accuracy spread, and prediction disagreement. Report the ensemble-minus-parameter-average and post-KD-minus-ensemble gaps. | Teachers and their uniform probability average exist inside [`kd_utils.py`](../../src/fedmaq/core/kd_utils.py#L75); their predictions are not saved now. |
| Does the proxy set support the target? | Proxy class counts from its existing selection record, plus prediction entropy/disagreement on the actual proxy inputs. Keep any diagnostic use of proxy labels separate from the KD loss and future treatment selection. | [`get_server_loaders`](../../src/fedmaq/core/partitioning.py#L562) supplies separate proxy and validation loaders. |
| Could bit assignment or compression explain weak teachers? | Client partition ID, raw cap, soft quality target, applied bit width, client sample count, gradient norm, and norm of raw versus reconstructed update. For error feedback, distinguish raw-update distortion from corrected-update quantization residual. Aggregate teacher quality by applied width without publishing raw updates or per-example logits. | [`quantization_planner.py`](../../src/fedmaq/core/quantization_planner.py#L457) has the assignments; [`compress_and_reconstruct`](../../src/fedmaq/core/client_hooks/training_skeleton.py#L126) and the post-process hook see the updates and residuals. V1 saves only round-level summaries. |

Use a diagnostic schema that records the split, condition, seed, round, partition and proxy identities, code/config hashes, `post_process` state, observer cost, and the existing communication counters. Avoid storing full per-example logits or model tensors unless a later question needs them. Check that adding observers leaves a short deterministic treatment run's model outputs, assignments, and method-byte counters unchanged when compared with instrumentation disabled.

## Author-run diagnostic sequence

1. The observer is implemented under a separate diagnostic identity. A synthetic strategy check confirms the same returned aggregate and method-byte metrics with the observer off/on; a real MobileNetV2GN forward-pass smoke confirms the diagnostic model path. These checks do not replace an end-to-end short training smoke on the exact author checkout. Compare that smoke's model output, assignment trace, and byte counters with the observer off/on before the pilot. It is not a V2 result.
2. Prepare four 100-round, author-run diagnostic cells: full FedMAQ and `fedmaq_no_kd` at CIFAR-10 alpha 0.1/seed 123, and the same pair at alpha 1.0/seed 42. Use the **benchmark's** `post_process=true` setting and `split=val` for every cell. Reuse the same partition, proxy, validation set, and modeled-memory assignment within each pair. These seeds were selected after reading V1 outcomes to expose severe-skew instability and a milder-skew comparison, so the pilot is exploratory. The full-FedMAQ runs supply same-round checkpoints; the no-KD runs supply closed-loop controls. Before preparing run commands, verify that `kd_epochs` is the only treatment difference within each pair; algorithm labels and diagnostic metadata may differ. Record the resolved configuration hashes. Extend to other seeds or datasets only if this pilot cannot distinguish the hypotheses; a single seed per condition cannot establish an average treatment effect.
3. Plot each seed's validation accuracy and loss for parameter average, ensemble, post-KD student, and no-KD control against round and cumulative bidirectional bytes. Present per-class and teacher-quality summaries beside those curves. Do not pool conditions before inspecting their individual traces. Report the diagnostic's added actual runtime separately.
4. Use the observations to nominate one isolated KD or model-aggregation branch, or retain the no-KD anchor if no change has a defensible mechanism. Register exact treatment settings, controls, validation/holdout use, budgets, seeds, stopping and advance rules in #120 before any V2 treatment dispatch. Existing baseline curves remain historical context; a new-seed superiority claim requires targeted matched comparators or explicitly descriptive wording.

## How the diagnosis controls the paper shortlist

| Observed pattern | Candidate V2 question | Paper role, subject to the source's transfer limits |
|---|---|---|
| Ensemble beats the parameter average, but the post-KD student loses much of that advantage or worsens. | Student warm start, optimizer, update strength, or KD schedule. | [FedBE](../../../fedmaq-literature/docs/audits/2026-09-24-server-kd-paper-shortlist.md#citation-priority-for-the-initial-v2-scope) is the first new thesis citation; already-cited FedDF is the server-KD comparison. |
| Some teachers are useful on validation classes while the uniform ensemble is weak or confidently wrong. | Teacher relevance, selective filtering, or pooling. Test each separately. | Already-cited DaFKD/FedGO; add Selective-FD for filtering, or Kovalchuk et al. only if a defensible reliability estimator and its data-access costs are specified. |
| Proxy predictions are ambiguous or cover classes unevenly despite a usable validation ensemble. | Proxy selection or calibration before changing teacher weights. | FedUA for proxy selection; Fan et al. for calibration only if measured. |
| The parameter average and individual teachers are both weak, with large update disagreement. | Model aggregation or client drift under the same memory and byte constraints. | Existing SCAFFOLD, FedNova, and FedDyn citations frame distinct mechanisms; none is adopted from this symptom alone. |
| Teacher quality tracks assigned width or measured update distortion, and feasible caps fall into the 9–15-bit ladder gap. | Separate bit-allocation diagnostic while keeping the power mean and quantizer fixed. | Existing QSGD, FedPAQ, DAdaQuant, AdaGQ, and LAQ-HC citations suffice for the initial question. The V1 histogram alone does not justify this branch. |

These patterns may coexist. None is an advance rule or a treatment choice; the first result can also be inconclusive. The instrumented run explains what V1 could not observe, while the eventual V2 protocol must distinguish exploratory diagnosis from confirmatory evidence.

## Prepared implementation and author handoff

- [`v2_diagnostic.py`](../../src/fedmaq/core/v2_diagnostic.py) writes `v2_diagnostic.jsonl` beside the usual run manifest and telemetry. It records ten scheduled snapshots at rounds 1, 2, 3, 5, 10, 20, 40, 60, 80, and 100. The normal round evaluation still supplies the full post-KD/no-KD trajectory. Every snapshot includes same-validation-set model and ensemble scores, per-class counts, teacher accuracies, proxy entropy/disagreement, client assignment and compression summaries, and cumulative bidirectional bytes. The diagnostic time is separate from modeled method time and excluded from the next method wall-time interval.
- [`v2_diagnostic_severe.yaml`](../../conf/matrix/v2_diagnostic_severe.yaml) and [`v2_diagnostic_mild.yaml`](../../conf/matrix/v2_diagnostic_mild.yaml) contain two matched cells each. Both use `post_process=true`, validation, 100 rounds, and an isolated `diagnostic` output group. Their diagnostic ledger and validation split keep them outside the registered downstream test evidence. The no-KD algorithm config differs from full FedMAQ only in `kd_epochs` under the current freeze; a test pins this parity.
- On the intended checkout, the author can review the two portable plans with `uv run python scripts/run_matrix.py --matrix v2_diagnostic_severe --dry_run` and `uv run python scripts/run_matrix.py --matrix v2_diagnostic_mild --dry_run`. Before a live pilot, record its exact commit and resolved configs, complete the short off/on smoke, and review the dry runs. The author then runs the matrices on JupyterHub and returns each group's `sweep_status.json`, manifests, standard logs, and `v2_diagnostic.jsonl`. Neither the current code-level checks nor a prepared command counts as dispatched evidence.
